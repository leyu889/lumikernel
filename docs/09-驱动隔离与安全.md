# 09 · 驱动故障隔离与安全加固（M12）

> 这一份回答两个问题：
> ① **驱动坏了，内核能不能活下去？**
> ② **内核有没有把"能防的攻击"真的防住？**

## 一、驱动故障隔离

### 做了什么

给每个受管理的驱动一个**显式状态**：`Up` / `Down(原因)`。

| 机制 | 位置 | 行为 |
|---|---|---|
| 健康门 | `dev/health.rs` | 驱动入口第一句查 `is_up`，`Down` 时**立刻 `Err`**，不碰硬件 |
| 设备级降级 | `dev/ata.rs` / `dev/ahci.rs` / `dev/nic.rs` | 命令超时、设备不推进队列 → `mark_down` |
| 快速拒绝计数 | 同上 | 每次被健康门挡下都计数，自检与日志用它证明"门真的拦住了" |
| 恢复 | `health::recover_all()` | 重新走初始化，成功即回 `Up` |

**关键设计决定：门要挂在"设备"层，不是"控制器"层。**
第一次实现把门放在 `ahci::read_sector` 里，结果 BIOS 路径走的是 IDE PIO，
注入完全不生效（自检 `down=0`）。挪到 `ata::read_sector`（IDE 与 AHCI
的共同入口）之后才真正拦住。

### 自检 60 证明的四件事

```
[ OK ] driver:  降级→拒绝→恢复 ok，拒绝 1 次，恢复后内容一致
```

1. 正常状态能读盘；2. 注入"控制器失联"后**立刻**返回 `Err`（不等超时上限）、
状态变 `Down`；3. `Down` 期间再读一次被健康门挡下（拒绝计数 +1）；
4. `recover` 之后同一块盘内容**逐字节一致**。

### 边界（不能吹的部分）

这**不是能力隔离**。驱动仍跑在内核态，一次越界写照样能毁掉内核。
要做到那种隔离，得把驱动搬进独立地址空间（微内核）——那是另一个量级的工程。
这一层解决的是"**设备失灵**"，而它在真机上比内存越界常见得多。

## 二、安全加固

| 项 | 状态 | 说明 |
|---|---|---|
| **SMEP** | 代码就位，VBox 下 `cap=0` | 内核态执行用户页立即 `#PF`，堵死"用户页放 shellcode 骗内核跳过去"。VBox 默认不透传 `CPUID.07H:EBX[7]`，真机才有 |
| **W^X 审计** | ✅ **1540 页 0 违规** | 遍历页表确认没有"可写且可执行"的页。审计范围是用户区 + 内核映像区；直接映射区的 2 MiB 大页是 `boot.S` 铺的（RW、未置 NX），NX 化需要改引导页表构造，单独留待下一步 |
| **SMAP** | 只探测，不启用 | 内核读用户内存也要 `stac`/`clac`。我们的用户内存访问还有几处历史路径没收敛进 `uaccess`——没改完就开它是**负收益**（一个漏改点让正常程序随机 `EFAULT`） |
| 栈金丝雀 | ✅（M11） | 高水位实测 65 KiB / 256 KiB |
| unsafe 密度 | ✅ 1.53%（SLO ≤5%） | 见 `docs/unsafe-register.md` |

### 为什么 SMEP 判定要分"能力"与"状态"

`security: SMEP=0（cap=0）W^X 违规=0` —— 这一行读作：
**CPU 没报告支持 SMEP（所以没开），但 W^X 审计是干净的**。

如果把"SMEP 没开"直接判成 FAIL，虚拟环境会永远红；判定口径应当是：

- `cap=1` 且 `SMEP=0` → **FAIL**（我们的代码有问题）
- `cap=0` → **信息**（环境限制，不是缺陷）
- `W^X 违规 > 0` → **永远 FAIL**

## 三、这一轮抓到的、值得写下来的坑

1. **`dequeue` 摘运行态任务是静默失败**——`block_current` / `exit_current` /
   `wake` 三处都踩了。运行态不在就绪队列里，`dequeue` 只摘 `READY`，
   于是槽位带着 `RUNNING` 泄漏，泄漏到上限后 `spawn` 全部 `Duplicate`，
   **内核线程从此再没被调度过**。修法是 `ksched::detach()`。
2. **`me()` 不能进 syscall 热路径**——它读 APIC MMIO，VBox 里一次 = 一个
   VM exit。`current_index()` 每调一次就慢 40 µs，syscall 整体慢 **110 倍**。
3. **CPUID 的 ECX 必须显式给 0**——leaf 7 用它选子功能，留成 `lateout`
   会拿垃圾值去查，结论是"CPU 不支持 SMEP"。
4. **virtio 的 used 环必须 4096 对齐**——队列只分配一页时它落在页外，
   读回来全是 `0xFFFFFFFF`。
5. **FAT16 的总扇区数有两个字段**——小卷用 16 位那个，只读 32 位会得到 0，
   簇数算成 0 直接被拒。
6. **TX 环判满不是 `TDH == tail`**——初始 `TDH=0`、`tail=0`，第一次发包
   就被误判环满。正确判据是 `(tail+1) % N != TDH`（留一个空位区分空/满）。
