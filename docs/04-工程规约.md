# 04 · 工程规约与已踩的坑

## 一、代码规矩（十个包一律生效）

1. `#![cfg_attr(not(test), no_std)]`，**零第三方依赖**。
2. 不许 panic：不用 `unwrap()`/`expect()`（测试除外），不用 `assert!`（用 `debug_assert!`）。
3. 不许隐式分配：分配必须显式传入，OOM 是正常返回值。
4. 每个 `unsafe` 上面一行 `// SAFETY:`，说清"为什么这里安全"。
5. 与硬件打交道的部分走 trait（`PageProvider`、`BlockDevice`、`Clock`），测试用 mock。
6. 公开 API 写中文文档注释；`cargo doc` 零 warning。
7. 提交前：`cargo test -p <crate>` 全绿 + `cargo clippy` 零 warning。

## 二、构建与验证

```bash
python build.py --ver 0.1        # 编译内核 + 引导链 + 打 ISO + 结构校验
bash scripts/vmtest.sh <iso> 8   # VirtualBox 无头启动，抓串口日志 + 截图
```

**串口是这个项目的主调试通道**，不是截图。截图只能看"有没有字"，串口能看"死在哪一行"。

## 三、已经踩过的坑（别再踩第二次）

### 1. stage1 的头部固定读 1120 扇区
`boot/boot.asm` 的头装载写死 1120 扇区（573 KiB），尾部装载数是 `KERNEL_SECTORS - 1120`。
内核比这个窗口小时，减法**下溢成 6 万多扇区**的死循环——症状是 stage2 打完 `k` 就再没动静，
既没有异常也没有重启，看起来像"内核入口没执行"。
→ 构建脚本必须按 `max(实际扇区, 1120)` 上报（`build.py` 已处理）。

### 2. SSE 未启用会在第一行 Rust 代码处 #UD
`stage2` 只开了分页，没开 `CR4.OSFXSR`。x86_64 编译器基线带 SSE2，
优化器随手一条 `movdqu` 就触发 `#UD` → `#DF` → 三重故障。
→ 内核入口必须设 `CR0.EM=0, CR0.MP=1, CR4.OSFXSR|OSXMMEXCPT`。

### 3. IDT 装载前必须 cli + 屏蔽全部 IRQ
BIOS 交班时 IF 可能是 1，PIC 的 IRQ0 还在跑，而 IDTR 还是实模式默认值。
一个时钟中断就足以把系统打进三重故障复位循环。
→ 入口第一条指令 `cli`，紧接着 `outb(0x21,0xFF); outb(0xA1,0xFF)`。

### 4. 串口日志文件必须先创建
VirtualBox 的 `--uartmode1 file` 后端要求目标文件已存在，否则一直是 0 字节。
→ 脚本里先 `: > serial.log`。

### 5. 关机要用 ACPI 软关机
硬 `poweroff` 会丢掉 UART 缓冲区里没 flush 的数据，日志缺尾。
→ `acpipowerbutton` 并轮询到真正 `poweroff`。

### 6. 重挂 ISO 前必须先卸载
VBox 会按"路径 + 介质"缓存光盘内容，直接重挂可能还在跑旧盘。
→ `storageattach ... --medium none` 再挂新的。

### 7. 虚拟机被上一次会话锁住
`VBoxManage` 报 `already locked for a session`，说明上一台 VM 还在跑。
→ 先 `controlvm <vm> poweroff`，等状态变 `poweroff` 再启动。

### 8. global_asm! 的依赖不会被 cargo 追踪
改了 `boot.S` 但产物没变，是**最常见的假象**。
→ `lumikernel/build.rs` 里声明 `cargo:rerun-if-changed=src/boot.S`。

### 9. 改了代码必须确认产物真的变了
判据不是"编译成功"，而是**二进制里的字节变了**（或文件大小/哈希变了）。
→ 关键改动后 `python -c "print(open('build/kernel.bin','rb').read(16).hex())"` 核对。

### 10. 内核高半区落在 PDPT 的第 510 项，不是第 0 项
`0xFFFFFFFF80000000` 属于 PML4[511] 覆盖的最后 512 GiB，但它在其中的**倒数第二个 1 GiB 槽**（下标 510）。
按"基址就是槽 0"去写 `pdpt[0]`，现象是：`mov cr3` 之后读任何高半区地址立刻三重故障，
连串口都来不及打一个字。
→ 用 `addr >> 30 & 0x1FF` 算清楚再写；写完必须**读回来验证**，不要靠直觉。

### 11. 用了 NX 位就必须先开 EFER.NXE
`kpt` 给所有数据页写 `NX(bit63)`。若 `IA32_EFER.NXE=0`，这条 PTE 会被判成"保留位违规"，
访问时 `#PF`；在没有 IDT 的 M1 阶段，`#PF` 直接变三重故障。
→ `boot.S` 里 `rdmsr 0xC0000080 / orl 0x800, eax / wrmsr`，在做任何页表操作之前。

### 12. VGA 屏幕不会自己清，别把残留当成本次输出
VirtualBox 热复位时 BIOS 不保证清屏。屏幕上一行"像上次的输出"的字符，曾让我误判引导失败。
→ 内核 `console::init()` 里显式清 80x25 文本缓冲，并把 ROW/COL 归零。

### 13. 自检里"分配了帧"就必须"归还并断言计数归零"
M1 的页表自检一开始漏还了被映射的数据帧，8 项里就这一项 FAIL：
`自检结束后帧数没有回到起点（有泄漏）`。
→ 任何涉及资源的自检，最后一步固定是**计数回到起点**，否则等于没测。

### 14. 中断帧布局必须与压栈顺序逐字节一致，且要有编译期断言
`stubs.S` 里 `pushq` 的顺序、入口桩压 `vector/error` 的顺序、CPU 自动压的 5 项，
三者共同决定 `InterruptFrame` 的字段顺序。任何一处错位都**不会编译报错**，
只会打印出一堆"看起来像真的"的垃圾寄存器值——比崩溃更难查。
→ `frame.rs` 末尾用 `const _: () = assert!(size_of::<InterruptFrame>() == 176);` 卡住；
   新加寄存器必须同时改三处：汇编压栈、结构体字段、这个常量。

### 15. 调 Rust 之前必须把 %rsp 对齐到 16 字节
SysV ABI 要求 `call` 前 `rsp` 16 对齐；否则 Rust 里的 `movaps` 触发 `#GP`。
用中断门进 `isr_common` 时 `rsp` 的对齐是**未知的**（取决于被打断的代码）。
→ 在 `isr_common` 里 `movq %rsp,%rbp` 存帧顶 → `andq $-16,%rsp` → `call` → `movq %rbp,%rsp` 复原。
   在处理 `#GP` 的路径上再 `#GP`，直接三重故障，什么都看不到。

### 16. 8259A 必须重映射，否则 IRQ0 会盖住 #DF
上电后 IRQ0..7 落在向量 0x08..0x0F，正好压在 CPU 异常上（IRQ0→#DF，IRQ1→#GP）。
不重映射时第一次定时器中断会被当成双重故障处理，现象是"刚开中断就崩"。
→ ICW1..ICW4 把主片挪到 0x20、从片挪到 0x28，每条命令之间写一次端口 0x80 做 io_wait。

### 17. EOI 的顺序：先从片、后主片
IRQ8..15 的中断来自从片，从片的 EOI 必须先发，再给主片发；
顺序反了从片的 ISR 位一直挂着，那个 IRQ 从此不再进来（表现为"设备突然没反应"）。

### 18. 崩溃转储路径必须主动演练一次
"异常处理器写好了"和"异常处理器真的能打印现场"是两件事。
平时所有异常都被探针接住，崩溃路径根本不会执行，等于没验证。
→ `LUMI_CRASH_DEMO=1` 构建一个故意踩未映射页的镜像，真机跑一遍、截图存档
   （`docs/证据/M2-崩溃现场.txt`）。顺带用寄存器值反查栈帧布局对不对：
   `r12` 里应当还能看到上一步 guard page 用过的地址，说明寄存器保存/恢复是完整的。

### 19. 屏幕日志不要中英混排
VGA 文本模式没有中文字库，非 ASCII 字节只能丢弃。双语混排的句子被丢掉中文后
会留下"KiBBox/Vec"这种断句残字，比纯英文更难读。
→ 屏幕走**纯 ASCII 的 `tag: key=value`**（一行一个检查项，不折行），
   中文解释只走串口。两条通道各司其职，日志反而更好读。

### 20. 大结构体绝不能作为栈上临时值
`Scheduler` 有 4096 个槽位（≈128 KiB）。写 `let mut s = Scheduler::new(1);` 会先在栈上
造一整份再移动——内核栈只有 64 KiB，直接写到未映射区。
现象极具误导性：前面 16 项自检全过，然后在**任务初始化**里报一个
`#PF cr2=0xffffffffff0874c1`（野地址）、`rip` 指向正常代码。
→ 给这类结构加 **`init_in_place(&mut self, ...)`**，让它原地写静态区；
   `new()` 只留给栈够大的宿主机测试用。判断标准：结构体大小 > 栈的 1/4 就别放在栈上。

### 21. 重整 GDT 时，正在使用的选择子必须原样保留
`CS` 里存着加载时的选择子，`lgdt` 之后它不会自动失效。如果把 0x18 从"64 位代码段"
改成了别的东西，下一次远跳转就会用错描述符。
→ 新 GDT 的前几项与 stage2 保持一致（0x08/0x10/0x18/0x20），新段一律往后加；
   改完必须 `lretq` 重载 CS，并用 `sgdt`/`str` 回读校验。

### 22. 没有 TSS 就进不了 ring3
从 ring3 陷入内核时，CPU **不能**信任用户给的 rsp，它必须去 `TSS.rsp0` 取栈。
`TR` 没装载或 `rsp0` 是 0，第一次 `int 0x80` 就是三重故障——没有任何输出。
→ 建 16 字节 TSS 描述符 + `ltr`；每次切到用户任务都要 `set_rsp0(该任务的内核栈顶)`，
   否则会踩到上一个用户任务的栈（这种 bug 表现为"偶尔串输出"）。

### 23. 调度器不能把"正在退出"的任务改回就绪
`schedule()` 里无条件 `cur.state = Ready` 会把刚标成 Zombie 的任务复活，
于是父进程永远等不到子进程退出（`wait` 超时）。
→ 只有在 `state == Running` 时才退回 `Ready`；退出路径必须先把任务从调度器摘掉。

### 24. 自检失败也要把中断控制器配完
`intr::init()` 里 IDT 自检没过就提前 `return Err`，导致 PIC 没重映射 →
IRQ0 落在向量 8 上被当成 #DF → 现场全是错位的垃圾寄存器。
→ 初始化函数里"必须完成的动作"（屏蔽/重映射 PIC、装载 PIT）不能被自检结果打断；
   自检结果留到最后统一上报。

### 25. 崩溃路径要有一条绕开 `core::fmt` 的通道
异常处理器自己也可能有 bug，而格式化机是它最脆弱的一环（用到栈、trait 分派）。
一旦在打印中途再崩，就什么也看不到。
→ `console::raw_u64()`：只用移位 + `put_byte`，在 `crash()` 最开头先打出
   `V=`(向量) 与 `R=`(rip)。这两个数就能定位到"哪类异常、哪条指令"。

### 26. 16 位跳板里的 `lgdt` 不要乱加 `0x66/0x67` 前缀
AP 跳板实测崩在这里，而且**表现极具误导性**：BSP 一切正常、把三个 AP 都试了一遍、
每个都报 `online=false`；串口上则出现一串 `1\x0f` 洪水。
我一度把它读成"BSP 卡在 SIPI 的 ICR 写"，还写进了文档——那个结论是错的。

真相：`lgdt` 用了 `.byte 0x66, 0x67, 0x0F, 0x01, 0x16` + `disp32`。
`0x66` 把操作数当 32 位、`0x67` 把地址当 32 位，两者叠在一起装进去的 GDTR 是垃圾
（`sgdt` 读回 `limit=21341 base=0x53f000ff`，应为 `limit=39 base=0x80c0`）。
于是紧接着的远跳转 `jmp 0x08:0x802a` 查描述符表 `#GP` → 没有 IDT → 三重故障 →
VBox 复位那个核 → 它又收到待处理的 SIPI → 再跑一遍跳板 → 再死。

→ 规范写法只有 `0F 01 /2` + **16 位绝对地址**（跳板就在 1 MiB 以内，够用）：
```asm
    .byte 0x0F, 0x01, 0x16
    .word 0x8000 + (ap_gdtr - ap_tramp_start)
```
   修完立刻 `online=4/4`。
→ 教训不只是"前缀别乱加"，而是：**在实模式里用 sgdt/sidt 把描述符表读回来验证**，
   比盯着现象猜快得多。

### 26b. 两个核同时写同一个串口，得到的一定是假数据
AP 起来之后和 BSP 共用同一个 16550。两个 CPU 同时 `out 0x3F8`，
字节会互相覆盖；而且 `outb` 不等发送保持寄存器空就继续写还会丢字节。
表现为：标记字符错位（`[\x0fG]`）、相邻字节丢失、看起来像"代码跳飞了"。

→ **跨核探针走内存，不走设备**：跳板把阶段号写进 0x6000，
   BSP 事后读回来再统一打印（`smp::telemetry()`）。RAM 写不会丢，也不会互相踩。
→ 这条同样适用于以后的内核日志：多核下要打印，就得先有锁。

### 27. 虚拟机里别用 `pause` 做长延时
`core::hint::spin_loop()` 就是 `pause`。它在 VM 里可能触发 VM exit，
一次几微秒；循环八百万次就是几十秒——表现和死机完全一样。
→ 需要毫秒级自旋时，用带 `black_box` 的普通算术循环；需要精确时间用 TSC 或 PIT。

### 28. 初始化顺序：APIC 排在帧分配器之后
LAPIC/IOAPIC 的 MMIO 在 4 GiB 附近，不在恒等映射里，得先用页表映射；
建页表要中间层帧，帧分配器又得先读 E820。
早期把"装 IDT"和"起 APIC"塞进同一个 `intr::init()`，结果是 APIC **永远**
以"没有可用帧"失败，然后静默退回 PIC——自检全绿，但多核的事一点没做。
→ 拆成两段：`intr::init()`（只装 IDT）+ `intr::init_apic()`（内存就绪后再调）。

### 29. EOI 必须跟着中断控制器走
APIC 模式下写 8259A 的端口**不会报错**，但中断永远不会结束，
表现是"只来一次中断，之后彻底静默"。
→ `intr::eoi()` 里按 mode 分派；切模式时同步切 EOI 目标。

### 30. 每核计数器必须各自占一条缓存行（假共享）
四个核各自 `fetch_add` 自己的计数器，但 `WORK[1..3]` 只隔 8 字节，
落在**同一条 64 字节缓存行**上：每次加法都要把这条线在核间来回搬。
实测差距是 6100 万 vs 20 亿次——看起来像"核慢"，其实是假共享。
→ 用 `#[repr(align(64))] struct Padded<T>(T);` 把每核计数器隔开。
→ 这个 bug 不会报错、不会崩，只会在性能对比里露馅；所以性能类的自检要打印具体数值，
   不能只打印"通过"。

### 31. 校准时钟，不能用依赖被测对象的时钟当尺子
踩了两次循环依赖：
1. 用 PIT 通道 2 轮询当 10 ms 基准 → 那段延时实际 ~71 ms → APIC 定时器被校成 14 Hz；
2. 改用"PIT 的 10 个中断"当 100 ms → 实测仍只有 24 Hz，因为 PIT 那条链路
   （经 I/O APIC 投递）自己的频率也不是它声称的 100 Hz。

→ 最终用 **CMOS RTC 的秒边界**当基准：它是另一块晶振，与 APIC 定时器没有共享假设。
   结果 `init=9,999,980`（这台机器上 APIC 定时器就是 1 GHz），实测 94–99 Hz。
→ 通用判据：**能验证一个量之前，先找到一个不依赖它的参考**。找不到就先别下结论。

### 32. 多核同时满速空转时，别用 tick 数当墙钟
在"四个核一起空转"的 200 ms 窗口里量定时器频率，只数到 4 个 tick（≈20 Hz）；
同样的代码在 AP 都停在 `hlt` 时量，是 19–20 个 tick（94–99 Hz）。
原因：VirtualBox 的多 vCPU 会互相争 VM 锁，满速自旋时中断投递被显著稀释。

→ 量频率/延迟这类指标，必须在**静息态**下量，并写清楚测量条件。
→ 墙钟窗口用 TSC（`rdtsc`），不要用 tick；tick 的频率本身就是要验证的量。

### 33. 设备的块大小必须等于文件系统的块大小（512 vs 1024）
ATA 的物理扇区是 512 B，ext2 镜像的块是 1024 B。`kfs::mount` 会检查
`1024 << s_log_block_size == dev.block_size()`，不相等直接拒绝挂载。
→ 在**驱动层**做合并：`AtaDisk::read_block(lba)` 内部读两个扇区、拼成 1024 B，
   对外声明 `block_size() == 1024`。不要把"凑块"的活推给文件系统。

### 34. ATA PIO 的三个必查位，和一个不能多读的口
- 等 `BSY` 清之后**必须再查 `ERR` 和 `DF`**：只等 BSY 会把"设备报错"当成"数据就绪"，
  读出一整块 0xFF，然后在文件系统层报一个完全无关的"魔数不对"。
- 数据口必须**按 16 位读**（`inw`）。按字节读会得到高低字节重复的数据，
  现象是"每个字节都重复两次"，很容易被误判成设备坏了。
- `0x3F6`（alt status）每读一次就清一次中断标志：用它做 400ns 延时正好，
  但**不要在读数据期间反复读它**，否则 IRQ 会被吃掉（以后上 DMA 时会踩）。

### 35. ELF 的 `p_vaddr` 不能照搬：低地址已经是内核的
`0x400000` 这类地址在内核的恒等映射里是**内核页**（supervisor）。
把 ELF 段加载到那里并改成用户可执行，等于把内核暴露给用户态。
→ M5 的做法：所有段整体搬到固定用户基址 `0x4000010000`，入口做同样偏移。
   前提是程序位置无关（只用 RIP 相对寻址）。
→ 这是**临时方案**：M6 做 per-process 页表后，每个进程有自己的低地址空间，
   那时才能按 `p_vaddr` 加载，并顺手把"固定用户栈"也去掉。
   这类"临时方案"必须写进代码注释和 README，否则下一个人会当成设计。

### 36. 代码段只读，缓冲区就得放栈上
ELF 段的权限按程序头来（R+X / R+W）。把 `buf` 写在 `.text` 里，
用户程序 `read()` 时就会撞上写保护——这不是 bug，是 W^X 生效了。
→ 用户程序的临时缓冲一律放栈上（`mov %rsp,%r13; sub $N,%r13`）。
→ 这也顺便测到了 `copy_to_user` 的写权限校验：如果给一个只读页，
   `sys_read` 必须返回 `EFAULT` 而不是让内核崩。

### 37. 自己造的镜像，必须自己回读验证
`mkext2.py` 写完镜像会**用另一段独立代码**重新解析：校验超级块魔数、
块组描述符、根 inode、目录项链表、以及每个文件的内容逐字节比对。
→ 理由：造镜像和读镜像是同一套理解，写歪了往往"自洽地歪"。
   回读校验至少能挡住 rec_len、位图、inode 表偏移这类低级错。
→ 同理 `mkdisk.py` 把"汇编→ELF→镜像"串成一条命令：分三步手工跑，
   漏掉一步就会出现"内核跑的是旧程序"，而这种问题几乎无法从现象上看出来。

### 38. Windows 上两个会咬人的小坑（M5 实测）
- **Git-Bash 的路径转换**：命令行里写 `--file /bin/hello=hello.elf`，
  `/bin/hello` 会被 MSYS 改写成 `D:/Program Files/.../hello`。
  工具里要同时接受带/不带前导斜杠的写法，命令行里也别传绝对路径。
- **VBox 的介质注册表**：`disk.vdi` 挂过之后，直接 `rm` 文件会让注册表留下悬空条目，
  下次 `convertfromraw` 到同一路径直接 `E_FAIL`。
  必须先 `storageattach --medium none` + `closemedium disk <path> --delete`，再删再转。

### 39. 克隆内核页表，不能用"当前 CR3"当模板
进程切换之后 CR3 指向的是**某个进程的表**。这时候如果拿 `read_cr3()` 当
"内核模板"去复制高半区给新进程，复制出来的表里就带着上一个用户的低半区映射
——隔离当场失效，而且现象极其隐蔽（一开始所有测试都能过，直到两个进程
碰巧用到同一个虚拟地址才炸）。
→ 启动时用 `remember_kernel_cr3()` 记下内核 PML4，之后只用它当模板。
→ 判据：`new_user_table()` 里**不允许**出现 `read_cr3()`。

### 40. 切换 CR3 的时机：在 `switch_to` 之前
切换之后我们已经在对方的内核栈上了。内核栈走直接映射，两张表里都有效，
所以"先写 CR3 再 switch_to"是安全的；反过来（切完栈再写 CR3）也能跑，
但一旦以后内核栈换成 vmalloc 区（不在每张进程表里），就会立刻踩空。
→ 统一在 `switch_to` 之前写 CR3，并在注释里写清这个理由。

### 41. 用户段必须整体落在用户区内，且要有负测试
ELF 是**用户提供的输入**。把 `p_vaddr` 写成 `0xFFFFFFFF80200000`，
如果不检查，装载器就会往内核映像上建一个 user 页——等于用户程序自己开了后门。
→ 装载前检查：`entry` 与每个段的 `[vaddr, vaddr+memsz)` 都必须在
   `USER_LIMIT` 之下、且 `vaddr >= 4 KiB`（挡住空指针段）。
→ 必须有负测试：把真实 ELF 的 entry / p_vaddr 改坏，断言装载器返回错误。
   "我写了检查"和"检查真的生效"是两件事。

### 42. "并发"不能拿每进程 tick 数当证据
第一版把"两个进程都被 tick 记过"当并发判据，结果一直失败：
两个进程各跑 4 ms，**都短于一个 10 ms 时间片**，谁都没被 tick 记到。
→ 两处要改：让工作量明显跨过时间片（40M 次 ≈ 25 ms）；
  判据换成"窗口内的切换次数增量 ≥ 2"——它直接量的是"内核在它们之间切了"。
→ 同理，要证明"两个进程各打印了自己的内容"，光比字节数没用（两个都打印时字节数一样），
  得把输出真切一段下来比对（`console::capture_*`）。

### 43. 主动让出 CPU 必须记 vruntime，否则"让出"是免费的
`while flag == 0 { yield_now() }` 把整机卡死过一次：`yield_now()` 只调度、
不记 vruntime，空转任务的 vruntime 一直停在 1，调度器每次都挑它，
另一个就绪任务（正在 `hlt` 里等它退出）永远轮不到。日志停在上一行，
没有任何报错，看着像死机。

→ `yield_now()` 里先 `sched().tick(0, now, 1)` 给自己记一个时间片，再调度。
  Linux 的 `update_curr()`（在 deactivate 前结算）做的是同一件事。
→ 判据：**任何"主动放弃 CPU"的路径都要结算当前任务的运行时间**，
  否则抢占式调度会退化成"谁会赖着不走谁就赢"。

### 44. lost wakeup：检查状态与登记等待必须原子
"看缓冲区 → 发现自己该等 → 登记到等待队列 → 切走"这四步中间只要被打断一次，
唤醒就可能落在登记之前：数据已经在缓冲里，而我们正要睡下去等它。
现象是"偶尔卡死，重跑又好了"——最难查的一类。

→ 这四步全程 `disable_irq_save()` / `restore_irq()`。单核上关中断就等于
  "没有别人能插进来"；多核还要加锁，两个都做。
→ **放锁之后才能切走**：拿着锁 `switch_to` 会死锁（醒来之前没人能放这把锁）。

### 45. 阻塞调用外面不能套 `PreemptGuard`
抢占计数器是**全局**的，不是每任务一份。一个任务带着 `PreemptGuard`
睡下去，计数就永远高于 0，其他任务再也抢不动——系统看着在跑，
实际只在时钟中断里打转。

→ `sys_read` 的结构是：拿守卫校验用户页 → **放守卫** → 真正读（可能阻塞）
  → 再拿守卫把数据拷回用户内存。校验和搬运必须分开。
→ 自检最后加一条"抢占禁用深度 = 0"，任何泄漏都会在那里露出来。

### 46. EOF 与 EPIPE 的前提互斥，必须用两个管道测
第一版在同一个管道上先 `close_write`、再 `close_read`、再 `write` 期望 EPIPE，
实际拿到的是 `EBADF`——两端都关了，管道已经被回收，`used=false`。
**错误码不对不是实现错了，是用例本身不成立。**

→ 分两个管道：EPIPE 用"读端先全关、写端再写"；EOF 用"写端先全关、
  读端先读完缓冲、再读得到 0"。
→ 写这类用例前先问一句：这个顺序在真实使用里会发生吗？不会就是自嗨。

### 47. 进程退出必须回收页表页，而不只是"不再调度"
僵尸任务只是从运行队列里摘掉，它占的帧一页没少：1 个 PML4 + 若干中间表
+ 若干数据页 + 4 页内核栈。几百个进程就能把 512 MiB 吃干净，
而且**不报错、不崩**，只是越来越慢最后分配失败。

→ `task::reap(tid)`：走一遍低半区（PML4[0..256]）退掉每个叶子页与中间表，
  再退内核栈、关 fd、清槽位。高半区不能碰——那是所有进程共享的内核映射。
→ 判据必须是**可用帧数精确回到起点**（129332 → 129332），
  不是"看起来没泄漏"。差一页都算失败。

### 48. 按值返回的大结构体会先在内核栈上构造一遍
`kbcache::Cached` 在 `MAX_SLOTS = 64` 时约 66 KiB。`Cached::new()` 返回 `Self`、
`LumiFs::mount()` 也返回 `Self`，于是整块结构体**先在 64 KiB 的内核栈上构造**再搬走。
栈被踩穿，屏幕上是乱码 + 卡死，看起来像"文件系统把盘写坏了"。
（M3 那次是 `Scheduler` 128 KiB，同一个病。）

→ 大结构体的容量参数必须有上界，并且用**编译期断言**钉住：
  `const _: () = assert!(MAX_SLOTS * (BLOCK + 32) <= 16 * 1024);`
→ 判断标准：结构体 > 栈的 1/4，就不要让它出现在按值返回的路径上。

### 49. 日志的顺序只靠 `flush()` 保证，而 `flush()` 必须是真的
redo 日志的四段屏障：**载荷 → 屏障 → 提交记录 → 屏障 → 就地写 → 屏障 → 清记录**。
少任何一段，"先日志后数据"这个顺序在掉电后都可能反了——日志等于没写。

→ ATA 上的屏障是 `FLUSH CACHE (0xE7)`。设备内部有写缓存，不发这条命令，
  "已写入"只是"已进设备缓存"，掉电就没了。
→ 块缓存夹在中间时，`flush()` 必须先把脏块写回、再调设备的 flush；
  把写攒在内存里然后声称"已落盘"是最危险的一种实现。

### 50. 重放日志之后必须重读超级块
重放的内容里可能就包含新的超级块（空闲计数、事务序号）。只把块写到磁盘、
却继续用挂载时解析出来的那份内存副本，结果是"磁盘是对的、运行中的视图是旧的"，
下一次写就把旧值盖回去——症状是空闲块数越用越不对，而且**不会报错**。

→ `replay()` 末尾重读 `SB_LBA` 并重新解析；测试里断言 `free_blocks` 等于期望值。

### 51. inode 0 是合法编号，别拿 `ino != 0` 当"文件存在"
LumiFS 的 inode 从 0 开始，第一个文件就是 0。第一版自检写
`if lumifs_ok && m8_ino != 0`，于是"持久化"和"掉电重放"两项被静默跳过了，
日志里还显示 43/45——看起来只是两项失败，实际是**两项没跑**。

→ 用显式的 `have_file: bool` 表达"有没有文件"，不要用编号的真假值当判据。
→ 判据写错时，测试会以"失败"或"跳过"的形式骗人；所以每项自检的失败信息
  要能把"为什么没通过"说清楚，而不是只报一个布尔。

### 52. 系统盘只读、数据盘可写：破坏性实验要隔离
M8 起有两块盘：主盘 ext2（只读，装着要执行的文件）、从盘 LumiFS（可写）。
格式化、写坏、造掉电现场，全都只作用于从盘。

→ 这不是洁癖：如果只有一块盘，任何一次"为了测掉电而故意弄脏"的实验
  都可能让内核再也启动不起来，排查成本直接翻倍。
→ 顺带的好处是"数据盘没有文件系统就自动格式化"这种便利功能可以放心做，
  因为它不可能碰到内核依赖的数据。

### 53. 「写一个标记再恢复」的权限检查会污染用户内存
M9 早期，`copy_to_user` 的可写性检查是"探针往这一页写个 0xA5、再写回原值"。
它在 M5–M8 一直没出事，因为那些自检只写自己刚分配的内存。
到了 musl 的 `malloc` 就炸了：这个写-恢复序列落在页头，
而 mallocng 的组头正好在那里，一个字节的扰动就让"元数据指针"变成 `0xe0`，
表现是 `free()` 里空指针崩溃、`ls` 直接消失。

→ 改成直接读页表的 RW 位（`paging::page_writable_in`）：零副作用、还更快。
→ 教训：**任何"为了检查而临时改一下用户内存"的做法都要被怀疑**。
  检查的副作用必须为零，否则等于把检查本身变成了 bug 源。

### 54. `syscall` 指令不换栈、不压帧，入口必须自己拼
`int 0x80` 由 CPU 帮你切栈、压 rip/cs/rflags/rsp/ss；`syscall` 什么都不做：
它只把返回地址放 `%rcx`、RFLAGS 放 `%r11`，然后跳到你给的地址，`%rsp` 还是用户栈。

→ 入口第一件事是"存下用户 `%rsp`、换成内核栈"（全局变量，因为 `syscall`
  不读 TSS）。第二步是手工拼一个和 `InterruptFrame` 逐字节一致的 176 字节帧，
  然后**直接跳 `trap_return`**——和中断返回走同一条路。
→ 不要给 `syscall` 单独写一套返回逻辑：两套路径必然只有一套被测到。

### 55. `writev` 不实现，stdio 的输出会静默消失
musl 的 `printf` 最后走 `__stdio_write` → `writev`。M9 第一版只实现了 `write`，
于是 `ls /` 正常退出 0、**一个字符都不输出**。这比崩溃更难查：所有错误码都是 0。

→ 实现 `writev`/`readv`（按 iovec 逐段转给 `read`/`write` 即可）。
→ 判据：跑别人的程序时，"退出码 0 但没输出"要立刻怀疑**输出通道**（writev、
  ioctl 判定 tty、stdout 缓冲），而不是怀疑程序逻辑。

### 56. 初始栈的 auxv 项数不能写死
`argc/argv/envp/auxv` 是按 SysV 摆的。第一版把 auxv 的项数写成常量 14，
实际会写 15 对（PHDR/PHENT/PHNUM + 11 个固定项 + AT_NULL），
多出来的 16 字节正好越过预留区、把 `argv[0]` 的字符串盖成 0。
busybox 的报错是 `: applet not found`（程序名是空串），看起来像 applet 表坏了。

→ **先构造 auxv 向量，再按它的实际长度算指针区大小**。
→ 摆完必须**读回校验**（argc、argv[0] 的内容），错位时直接返回 `EINVAL`，
  而不是让用户程序以"什么都不做"的方式失败。

### 57. 目录游标不能用 `lseek`
`lseek` 对目录返回 `EINVAL` 是对的；但 `getdents64` 内部要推进游标，
第一版顺手复用了 `fd::seek`，返回值被 `let _ =` 忽略 → 游标永远不动 → `ls` 死循环。

→ 目录游标走独立的 `fd::set_off`，并在注释里写清"这里不能用 lseek"。
→ 任何 `let _ = expr;` 都是在赌"这个调用不会失败"；要么处理，要么写清楚为什么可以忽略。

### 58. `ioctl(TCGETS)` 别假装自己是终端
为了让 `isatty()` 为真，第一版回了合法的 `termios`。结果 `ls` 判定 stdout 是终端，
给每个名字套 ANSI 颜色，屏幕上出现一堆 `ESC[1;34m`。

→ 没有键盘驱动、没有行规程，就老实回 `ENOTTY`。
→ 通用原则：**能力没实现时，让探测失败**。假装支持会把问题推迟到更难查的地方。

### 59. `mmap(MAP_FIXED)` 必须"覆盖"，不是"撞车就报错"
musl 的 `alloc_meta` 会先 `brk` 出两页、再把第一页用
`mmap(PROT_NONE, MAP_FIXED)` 变成 guard。第一版 `mmap` 遇到"这个地址已经有映射"
就直接返回 `ENOMEM`，于是 malloc 拿不到元数据区，后续一路崩。

→ `MAP_FIXED` 的语义就是覆盖：先 `unmap` 区间里已有的页（并把帧还回去），再建新映射。
→ 顺带加了"新帧不能已经映射在本地址空间"的硬检查，专门抓"一帧两用"。

### 60. 跑别人的程序时，用户态异常必须只杀进程
`#PF`/`#GP` 从 CPL3 来的时候，那是用户程序的 bug，不是内核的。
第一版直接走 `crash()` 停机——`ls` 里一个空指针就把整机打死，而且看起来像内核崩了。

→ `f.cs & 3 == 3` 时：打印 `vector/error/rip/cr2` + 最近的系统调用轨迹，
  以 139（128+SIGSEGV）退出该进程，内核继续。计数在 `handler::user_faults()`。
→ 打印"最近 24 次系统调用"比打印 20 个寄存器有用得多：M9 里两次定位都是靠它。

### 61. `GetMemoryMap` 的参数顺序是 (MapSize, **Map**, MapKey, DescriptorSize, Version)
写成 (MapSize, MapKey, …) 的后果不是报错，而是固件把整张内存图**写进你那个
8 字节的 map_key 变量**——栈当场被砸穿，然后 RIP 跳到一个莫名其妙的地址（#UD/#GP）。

→ 抓症状：**#UD + RIP 落在低地址 + 寄存器里有可打印字符**，基本就是"固件按你的指针写了太多"。
→ 所有 UEFI 服务函数都先核对一遍签名再调用，别凭记忆填参数。

### 62. 固件页表把数据页标成 NX：内核不能放在 `EfiLoaderData` 里
用 `AllocatePages(AllocateAddress, EfiLoaderData, …, 0x100000)` 把内核放好、
跳过去执行，第一条取指就 #PF——没有 IDT，三重故障重启。
**`EfiLoaderCode` 才是"要执行的代码"**，固件会给它可执行权限。

### 63. `CR4.PCIDE` 开着时 `mov cr3` 不刷 TLB；清它又要求 CR3[11:0]=0
两个约束互相咬住：直接清 PCIDE 会 #GP（固件的 CR3 可能带非零 PCID），
直接 `mov cr3` 又不刷表。正确顺序是"写一次 CR3（顺带把 PCID 清零）→ 清 PCIDE →
再写一次 CR3"。
**结论：能不自建页表就别自建**——最后我们把内核页按 `EfiLoaderCode` 分配，
完全绕开了这一整类问题。

### 64. `ExitBootServices` 之后，固件栈和 BootServices 内存都不再属于你
- 栈是 `EfiBootServicesData`，会被释放：**跳转前必须换到自己的栈**
  （症状：串口打出 'C' 之后立刻重启——因为下一条 `push` 踩空）。
- GDT/GDTR 若放在栈上，`lgdt` 读到的是已释放内存，远跳直接 #GP：
  **描述符表一律放静态区**。
- 退出失败是常态（内存图 key 失效），要写成"退出失败 → 重取图 → 再退出"的循环。

### 65. 长模式下换 CS 用 `iretq`，别用 `retf`
`push 选择子; push 偏移; retf` 在纸面上成立，实测直接挂。
`iretq` 一次把 rip/cs/rflags/rsp/ss 全设好，语义没有歧义，也不依赖当前的段缓存。

### 66. 内核入口的传参寄存器会被 `rep stosb` 冲掉
boot.S 清零 `.bss` 时用 RDI 当目标指针（结束时 RDI=__bss_end），
于是"装载器用 `%edi` 传 E820 表地址"根本到不了 `kmain`。
→ E820 表固定在物理 **0x9000**（BIOS 链本来就这么约定），并在 memset 前后 `push/pop rdi`。
→ 教训：**汇编启动代码里的"入参"必须在第一条指令就保存**，不能指望它活过整段初始化。

### 67. VirtualBox 的 EFI 不认 El Torito 的 EFI 引导项
按规范把 EFI 段写进 El Torito 目录（平台 0xEF + 节头 0x90）也没用，
固件依旧报 `failed to load ... CD-ROM: Not Found`。
真机/固件真正走的是 **GPT → ESP(FAT) → `\EFI\BOOT\BOOTX64.EFI`**。
→ 所以 M10 的交付物是 `.img`（GPT+ESP），ISO 只保留 BIOS 那条链 + 一份 EFI 映像做备用。
→ 另一个细节：ESP 里的引导映像必须是 **FAT 文件系统**（哪怕用 El Torito 也是），
  固件会把它当磁盘挂起来找文件，不是直接加载裸 PE。

### 68. AHCI 命令头里的 CTBA 必须是**物理地址**；ABAR 可能是 64 位 BAR
设备只认物理地址，拿虚拟地址填 CTBA 会"命令发出去、永远不完成"（或者报 ATA 错误）。
ABAR 在真机上常常落在 4 GiB 以上，只读 BAR 低 32 位会映射到一片空地——
现象是"控制器找到了，CAP 读出来全是 0xFFFFFFFF"。用 `pci::bar64`。


### 69. `pd_1g` 紧挨着内核栈：栈溢出会静默改掉直接映射
`boot.S` 的 `.bss` 布局是 `pml4 → pdpt_* → pd_1g → stack`。栈向下长，
**溢出时第一个踩到的就是 `pd_1g` 的尾部**。后果不是"崩溃"，而是
"直接映射里某一段 2 MiB 悄悄失效"，要等到恰好分配到那片内存时才炸。

实测现场：`cr2=0xffff80002ca00000`、`error=0xb`（RSVD=1），
四级表项里 `pd_1g[357] = 0xffffffff8010f6cf`（一个返回地址）。

→ 栈与页表之间必须有**金丝雀页**；栈要留足余量（M11 从 64 KiB 提到 256 KiB，
  实测峰值 65 KiB —— 也就是原来**正好**差 1.2 KiB 就溢出）。
→ 并且要**量**：启动时给栈画图案，跑完扫第一个非图案字节 = 高水位。
  "够不够"变成数字，而不是等它炸。

### 70. `unmap` 会回收空的上级页表页 —— 所以绝不能对内核地址调用
`kpt::unmap` 在 PT/PD/PDPT 变空时会把它们还给帧分配器。
对**用户**地址这是对的；但如果传入一个高半区地址（直接映射 / 内核映像），
它会把**全系统共享**的 PDPT/PD 页还给分配器，于是所有进程的直接映射同时失效。

→ `unmap_in_current` 硬护栏：直接映射区与内核映像段一律 `Err`（vmalloc 放行，
  那是内核自己按需建的）。
→ `munmap` 也要校验 `addr..addr+len` 落在用户区内——否则一个垃圾寄存器值
  就能让内核去拆自己的页表。

### 71. 故障注入的判定要在拿锁之前，而且只能用原子量
注入点是"分配失败"，而分配失败的那一刻**恰恰可能拿不到锁**（锁的持有者
可能就是上一个失败者）。所以判定函数不能加锁、不能分配、不能打印。

→ 用 `AtomicU8`（当前注入点）+ 原子计数实现"第 N 次失败"的状态机，
  纯逻辑部分放 `kqa::fault::Plan`（宿主机可单测），内核只做"问一句"。
→ 预算用完自动解除，否则后续正常路径会被一直干扰。

### 72. 微基准必须跨系统用**同一份二进制**
拿 busybox 计时、再拿 Linux 的 busybox 计时，比出来的是"两个 busybox"，
不是"两个内核"。所以 M11 写了一个零依赖的 `bench`（`no_std` + 裸 `syscall`
+ `rdtsc`，6928 字节），**同一个文件**在两边的 shell 里都能跑。

→ 只用两边都实现的系统调用；计时只用 `rdtsc`（同一台物理机 = 同一个晶振）。
→ 差异要能解释：`mmap` 我们**不是**懒分配（Linux 只建 VMA），
  `fork` 我们**不是** COW（整页复制），这两项比出来的是策略差异，不是"慢"。


### 73. `dequeue` 对运行态任务是静默失败 —— 三处都踩过
`ksched::dequeue` 只摘 `READY`。`block_current` / `exit_current` / `wake`
都曾用它摘"当前正在跑"的任务 → 返回 false（被 `let _ =` 吞掉）→
槽位带着 `ST_RUNNING` 永远不回 free list。泄漏到上限后 `spawn` 全部
`Duplicate`，**内核线程无声消失**（三个自检连锁失败，现场毫无线索）。

→ 摘运行/任意态任务一律用 `ksched::detach()`。
→ 任何 `let _ = sched().xxx()` 都要问一句"失败了会怎样"。

### 74. 中断/系统调用热路径里不许出现 MMIO
`me()` 读 APIC 的 `local_id`，那是一次 MMIO——VBox 里等于一个 VM exit。
把它放进 `current_index()` 之后，**每个 syscall 慢 110 倍**（408 → 44.7K 周期）。
→ 热路径上的 CPU 标识要么缓存，要么在单核期间直接用 0。

### 75. 驱动健康门要挂在"设备"层，不是"控制器"层
把门放在 `ahci::read_sector` 里，BIOS 路径走 IDE PIO 就完全绕过它。
→ 门挂在 `ata::read_sector`（两种控制器共同入口）。

### 76. virtio 队列必须两页连续内存
used 环按规范要 4096 对齐；desc+avail 已经占掉一千多字节，
used 必然落在第二页。只给一页时读回来是 `0xFFFFFFFF`。
→ `alloc_frames(2)` + 整块清零。


### 77. legacy virtio 的 `QueueNum` 只在 `QueuePFN == 0` 时可读
先写 PFN 再读长度，读回来是 0——而代码会拿 0 去算布局，错误被自己掩盖。
顺序必须是：选队列 → 读长度 → 分配 → 填环 → 写 PFN → DRIVER_OK。

### 78. 16 位寄存器不能用 32 位读
`QUEUE_NUM` 在 0x0C、`QUEUE_SEL` 在 0x0E。用 `inl`（4 字节）读 0x0C 跨了
寄存器边界，VBox 与 QEMU 都直接返回 0。**寄存器宽度就是访问宽度**。

### 79. virtio-net 的缓冲是 `头 + 数据`，不是裸以太网帧
legacy 必须留 10 字节 `virtio_net_hdr`。发的时候填 0（不要 offload），
收的时候跳过 10 字节。少这一步，以太网头整体错位 10 字节。

### 80. 组包与解包用同一个错误偏移，单测永远发现不了
ARP 的 `ptype` 是 **2 字节**，代码里当 4 字节写、也当 4 字节读，
于是 `pr = 0x08000604`，收进来的每个回复都被判成坏包。
roundtrip 测试两边一起错照样绿。
→ 协议实现必须有**按线上字节逐位断言**的测试（见 `arp::tests::wire_bytes_match_rfc826`）。

## 四、验证纪律

- 先静态校验（`checkiso.py`），再进虚拟机。
- 一次只验证一层：引导能不能进 → 串口有没有字 → 内核自检过没过。
  上一层的结论没钉死之前，不要往下猜。
- 没有原始串口日志的"完成"，按未完成算。
