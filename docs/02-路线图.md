## 里程碑节奏（不是工期承诺）

- M0–M2：把"能跑、能看、能抓现场"三件事做扎实。这一段我自己写，不派助理——地基错一寸，上面全歪。
- M3–M6：十个工作包并行推进，每个包独立 crate、独立测试。
- M10–M11：收敛。这一段不写新功能，只做"证明它稳"（故障注入、fuzz、长跑、真机）。
- M10 把"真机才会暴露的问题"提前打出来了一大半（UEFI 页表 NX、PCIDE、退出引导服务后的栈与 GDT、
  SATA/AHCI 的 DMA 与物理地址），剩下的交给真实硬件验证。
- M11 没有加功能，只把稳定性做成可判定的：S1–S7 全部有脚本、有数字、有证据。
  顺带抓到并修掉一个真实的 boot 栈溢出（它会静默改掉直接映射的页表项）。

## M12 完成情况（2026-11-20，61/61）

| 项 | 结果 |
|---|---|
| fork 写时复制 | ✅ 12 µs（原 ~90 µs） |
| mmap 懒分配 | ✅ 171 万 → 806 周期 |
| wait4 立即唤醒 | ✅ wait_halts 195 → 0，fork+wait 61M → 51 K |
| 网络协议栈（knet） | ✅ **ping 通**（ARP + ICMP 端到端，VBox NAT） |
| virtio-net / e1000 驱动 | virtio-net ✅（队列按设备上报长度动态布局）；e1000 在 VBox 上链路不 up（PHY 模拟），保留作真机兜底 |
| FAT16/32 只读（kfat） | ✅ 端到端（挂载 + 目录 + 内容逐字节一致） |
| 驱动故障隔离 | ✅ 注入 → 立刻 Err → Down → 快速拒绝 → recover |
| SMEP / W^X | SMEP 就位（VBox 不透传 CPUID）；W^X 1540 页 0 违规 |
| SMP 多核调度 | 基础设施就位，**真并行未启用**（需 per-CPU TSS/GDT） |
| ext2 写入 | 不做（可写能力由 LumiFS 覆盖，改系统盘风险大于收益） |

## M12 之后的待办（按性价比排序）

1. `wait4` 立即唤醒（现在是等 tick，`fork+wait` 因此多花 10 ms）
2. `fork` 写时复制
3. `mmap` 懒分配（改完才谈得上和 Linux 比这一项）
4. ext2 读路径接 `kbcache`（现在只有 64 块直连缓存）
5. guest 侧常驻压测 workload，把 30 天长跑做成"不重启"
6. 43 处 unsafe 的模块级证明就地化

## 每个里程碑的固定动作

1. 代码合入前：`cargo test --workspace` 全绿 + `cargo clippy` 零警告。
2. 合入后：`scripts/run-qemu.sh` 启动，检查串口里没有 `panic` / `FAIL`。
3. 里程碑收尾：更新本文件状态列 + 在 `docs/证据/` 下留一份原始日志。

> 规矩：**没有原始日志的"完成"，一律按未完成算。**
